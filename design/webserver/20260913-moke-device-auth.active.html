Moke 密码直登与设备 API Key

让已有 TaleBook 账号绕过访客访问码直接登录，并用可吊销的设备密钥恢复短期 Cookie 会话，同时保持现有书籍权限边界。

状态：ACTIVE创建日期：2026-09-13所属模块：webserver影响范围：认证、数据库迁移、Moke 客户端需求来源：用户确认的实施计划

1. 原始诉求

已有账号应直接使用用户名和密码登录，不要求先输入访问码；增加长期有效、可随时吊销的设备 API Key，用于自动恢复登录 Cookie。API Key 只能换取会话，不能直接访问书籍、管理或下载接口。

2. 目标与边界

  • 访问码只服务匿名访客，密码登录与设备密钥登录均不受访问码前置拦截。
  • 保留验证码、演示模式、账号启用状态、密码和权限检查。
  • 原始密钥只返回一次；服务端只保存 SHA-256 哈希与可展示前缀。
  • Bearer 密钥只在 /api/user/api_key/sign_in 验证，不扩展全局认证。
  • 不修改 Cloudflare 私有内容缓存规则，不迁移或删除 TaleBook 数据目录。

3. 接口与流程

1. 密码登录校验验证码、账号与密码，写入登录和访问 Cookie。
2. 记住设备吊销同账号同设备旧密钥，生成一次性返回的新密钥。
3. 安全保存Moke 将密钥写入系统安全存储，不进入 URL、缓存或日志。
4. 会话恢复Cookie 失效后只向专用端点提交 Bearer 密钥并换取新 Cookie。

接口

接口认证行为
GET /api/welcome公开附加密码直登和设备密钥能力标记。
POST /api/user/sign_in账号密码绕过访问码；可按设备创建或轮换密钥。
POST /api/user/api_key/sign_inBearer 设备密钥仅换取 Cookie，会更新最后使用时间。
GET /api/user/api_keysCookie仅返回本人密钥元数据。
POST /api/user/api_keysCookie + 当前密码手动创建或轮换设备密钥，原始值只返回一次。
DELETE /api/user/api_keys/{id}Cookie仅吊销本人密钥。

数据模型

reader_api_keys 保存账号、设备 ID、名称、前缀、SHA-256 哈希、用途、创建时间、最后使用时间、可选过期时间和吊销时间。每账号最多 10 个有效密钥；同设备创建时先吊销旧密钥。

4. 安全与兼容性

  • 密钥格式为 moke_tk1_<prefix>_<secret>，随机值来自操作系统加密随机源。
  • 先按前缀查找候选，再用常量时间比较哈希；响应、普通请求日志和异常日志均不包含完整密钥。
  • 旧数据库启动迁移会创建完整新表；创建失败时启动检查失败并停止部署。
  • 旧客户端不传新字段时沿用原登录响应；旧服务器能力缺失时 Moke 不展示设备密钥功能。

6. 决策记录

  • 2026-09-13：密钥长期有效直到吊销，且只用于换取 Cookie 会话。
  • 2026-09-13：密码登录默认记住设备；同账号同设备重新登录会轮换密钥。
  • 2026-09-13：鸿蒙当前没有可靠系统密钥链，只支持会话内 API Key，不长期保存。
  • 2026-09-13：TaleBook 不新增管理 Web UI，设备管理界面由 Moke 提供。
  • 2026-10-12：合并实时 main，并保留弱网缓存/超时/并发合并；认证请求最多恢复一次，写请求不套通用网络重试。恢复绑定请求开始的服务器及账号对象，切换账号、同账号重新登录、服务器改变后拒绝迟到结果。
  • 2026-10-12：补齐 Moke 原生下载及缓存命令的显式 ACL；恢复升级前已存在文件的原生下载索引，只检查文件元数据，不重新读取或哈希整本书；Reader 出口忽略残留原生按键拦截标志。
