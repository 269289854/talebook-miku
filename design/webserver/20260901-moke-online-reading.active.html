Moke online reading and cache optimization

Native Moke platforms add on-demand EPUB/PDF reading, reduce TaleBook bandwidth and database writes, improve downloaded-book cold start, and expose cache cleanup without affecting downloads or reading progress.

Status: ACTIVECreated: 2026-09-01Module: webserverScope: Moke / Readest / TaleBook / deploymentSource: user online-reading and cache request

1. Original request

Online reading is missing. Downloaded books are slow on first open. Prefer local cache to reduce the small server bandwidth budget, and provide manual cache cleanup.

The private production library must keep authentication, visibility, download permissions, Range behavior, and the Cloudflare proxy configuration. No public cache rule will be added.

2. Goals and boundaries

Goals

  • Native Tauri platforms support on-demand Range reading for EPUB/PDF; the first screen does not download a complete file.
  • Downloaded files open from their local path without MD5 precheck or transient import.
  • Desktop cache limit is 2GB; mobile cache limit is 512MB; LRU reclaims space.
  • Settings expose reader, image/API, and all-cache cleanup while preserving downloads, notes, settings, and progress.
  • mode=read preserves permission checks but does not write download history or increment download counts.

Non-goals

  • Web online reading is outside this iteration.
  • TXT and conversion-heavy formats remain download-first.
  • No full TaleBook upgrade, data migration, or recreation of /data/talebook.
  • No commit, push, tag, release, or Cloudflare public book cache.

5. Implementation

Decision: Moke owns account-scoped cache policy, Readest owns direct local/remote source bootstrap and 128KB block cache, and TaleBook serves a private permission-checked Range stream. Native API/image responses prefer the app-private AppCache subtree and fall back to Cache Storage or memory; persisted metadata never stores cookies, passwords, tokens, authorization headers, or sensitive query parameters.
SourceMokeBookSource

One local/remote contract containing server, account scope, book, format, title, author, and file version.

ReaderDirect bootstrap

Remote source reads on demand; local source skips MD5 and transient import.

Cache128KB blocks

Return cache hits immediately, persist asynchronously, invalidate on ETag change, merge identical concurrent ranges.

ServerRead mode

Inline MIME, private no-cache, and no download side effects for HEAD/Range; Moke records a successful open once through POST /api/book/{id}/readstate with online_read=1.

Protocol and quotas

GET /api/book/{id}.{format}?mode=read; Range: bytes=<start>-<end>; ETag: <file-version>; Mobile reader 384MB + image/API 128MB; Desktop reader 1.5GB + image/API 512MB; at 110% clean down to 90%.

Compatibility

  • open_reader keeps the legacy filePath parameter and accepts the direct source.
  • Local and remote sources share a stable book identity; a file-version change isolates old cache blocks.
  • Logout clears only current-account non-download cache; an event tells an active Reader to release memory blocks.

6. Risks and rollback

Risks

  • Bad proxy Range behavior: validate status, Content-Range, and length; never silently download the whole file.
  • Expired authentication: show re-login or download fallback; never persist credentials.
  • Cleanup race: Reader releases memory and refetches missing blocks; downloads remain in a separate directory.
  • Deployment failure: retain Compose, container config, image ID, and logs; restore the pinned digest.

Rollback

Client changes remain uncommitted. Server rollback replaces only the application image and restores the original Compose and pinned digest; /data/talebook is never migrated, deleted, or recreated.
