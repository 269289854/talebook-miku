运行、构建、发布与文档全部脱离上游 talebook/talebook

把版本检查、在线服务默认值、镜像发布、构建依赖、流水线容器和对外链接从上游 talebook/talebook 及原作者账号迁到本仓库所有者 269289854 名下；上游维护的构建产物通过 fork 与镜像复制固定到自己的账号，升级时机由本仓库决定。

创建日期：2026-10-14 所属模块：project（影响 webserver、app、docker、.github、文档） 状态：ACTIVE 需求来源：“这个项目也要和上游脱钩，别耦合上游项目。”

1. 原始诉求

“你来改，还有这个项目也要和上游脱钩，别耦合上游项目。”

本仓库由上游 Talebook 修改而来，但运行时仍会访问上游服务，构建依赖上游发布的产物，镜像名、流水线容器和界面链接也都指向上游。上游删库、改版或下线服务时，本仓库的构建与用户的服务器都会受影响。

类型内容
目标用户服务器默认不再连接上游：版本检查查本仓库 Release，阅读同步与邮件默认值留空，由管理员自行配置。
目标构建只从本仓库所有者的账号拉取依赖：基础镜像、语音库、有声书命令行子模块。

非目标docker/*-patch.Dockerfile 通过构建参数接收基础镜像，不依赖上游，保留不动。

3. 现状、根因与证据

类别现状
运行时update_checker.GITHUB_REPO = "talebook/talebook"；CANDLE_READER_SERVER 与 BRS 插件默认 https://brs.talebook.org；邮件默认 smtp.talebook.org / sender@talebook.org；反馈与首页 Star 链接、插件主页与 User-Agent 指向上游。
构建依赖Dockerfile 基于 talebook/talebook-base:slim-v8.5.0；voicebook-tool 从 talebook/voicebook 下载；子模块 talebook-audio-cli 位于原作者 hehetoshang 账号。
镜像与流水线build.yml 同时推 Docker Hub 与 GHCR，但仓库没有 Docker Hub 凭据，构建从首次运行起即失败；ci.yml 在上游镜像 talebook/talebook-base:latest 中测试；codex/claude 流水线使用上游 talebook/talebook:dev；Makefile、compose、Kubernetes 使用 talebook/talebook。
触发分支ci.yml 与 build.yml 只在 master 触发，本仓库默认分支为 main，CI 没有任何运行记录。
链接与文档页脚、帮助菜单、管理设置提示、主题模板、README、SECURITY 等指向上游；SECURITY 的漏洞上报邮箱为上游作者邮箱；FUNDING 为上游作者赞助入口。

阅读器 candle-reader 产物中写死的 https://api.talebook.org 只是未传参时的兜底值；creader.html 初始化时传入 server: window.location.origin ，因此不构成运行时耦合。

4. 方案

关键决策（已与仓库所有者确认）

决策选择
镜像仓库只发布到 GHCR，使用自带 GITHUB_TOKEN ，去掉 Docker Hub。
上游构建依赖fork 代码仓库并复制固定版本的基础镜像到自己的 GHCR，构建只从自己的账号拉取。
Candle Reader保留跟踪上游，只修权限。
在线服务与名称默认值清空，保留 Talebook 名称。

实施内容

  • GitHub 侧：fork talebook/voicebook 与 hehetoshang/talebook-audio-cli 到 269289854；新增 mirror-base-image.yml ，用 docker buildx imagetools create 把 talebook/talebook-base:slim-v8.5.0 连同全部架构复制到 ghcr.io/269289854/talebook-base ；开启 talebook-miku 的私密漏洞报告。
  • 构建与部署：Dockerfile、ci.yml 使用同一个已同步的基础镜像 tag；build.yml 只推 GHCR，PR 构建也登录以拉取私有基础镜像；codex/claude 容器改用 ghcr.io/${{ github.repository }}:dev 并补 packages: read 与容器凭据；Makefile、compose、Kubernetes 镜像名改为 ghcr.io/269289854/talebook-miku ；ci.yml 与 build.yml 改按 main 触发。
  • 依赖：requirements.txt 改从 fork 下载语音库，.gitmodules 改指 fork。
  • 后端：版本检查查本仓库 Release；CANDLE_READER_SERVER 、BRS 插件默认地址、smtp_server 、smtp_username 默认留空；反馈、首页 Star、插件主页、User-Agent 与电子书制作者信息改指本仓库。
  • 前端：页脚与帮助菜单链接改指本仓库与 GHCR 包页，删除上游官网链接；管理设置的 Logo 文档链接、客户端下载链接（改为 269289854/moke-miku）与主题模板同步修改。
  • 删除不再使用、基于上游发布镜像打补丁的 docker/moke-online-reading 。
  • 文档与工具：README（中英）、CODE_WIKI、开发与使用文档、SECURITY 改指本仓库；删除上游作者的 FUNDING 与向上游官网提交数据的 tools/update.sh ；产品技能脚本默认仓库改为本仓库。README 注明基于上游修改（GPLv3 要求）。
  • 测试：新增 tests/test_upstream_decoupling.py 扫描运行、构建与发布输入，禁止重新出现上游链接、镜像、官网与原作者账号；新增基础镜像 tag 一致性检查；同步更新受影响的流水线、Makefile、插件契约与前端测试。

5. 影响范围、风险与回滚

  • GHCR 新包默认私有。流水线已配置凭据，可以拉取；但最终用户要拉取 ghcr.io/269289854/talebook-miku 与本地构建使用的基础镜像，需要仓库所有者在包设置中改为公开。
  • codex/claude 流水线依赖 :dev 镜像，在本方案合并、main 首次构建推送 :dev 之前无法拉取。
  • 本仓库尚未发布 Release：版本检查会记录 GitHub API error: 404 ，帮助菜单“更新日志”打开空页面；发布首个 Release 后恢复正常。
  • 已有部署：保存过的设置不受默认值变化影响；只依赖默认值的阅读同步与邮件需由管理员填写地址。上游地址本就无法替代自己的服务，因此不会让原本可用的功能失效。
  • 镜像 tag master 改为 main ；此前从未成功发布过镜像，没有用户依赖旧 tag。
  • 删除的 docker/moke-online-reading 补丁中，后端在线阅读与书库排序改动已在源码中；其 nginx 缓存策略（/api/book/<id>.<fmt>?mode=read 返回 private, no-cache）未进入 conf/nginx 。后端在阅读模式下自行设置同样的 Cache-Control ，是否需要在 nginx 层补齐留待后续确认。
  • 回滚：还原本方案涉及的提交；GitHub 侧的 fork、GHCR 镜像与私密漏洞报告可保留，不影响回滚。
