为 Candle Reader 更新流水线申请推送与建 PR 权限

为 .github/workflows/update-candle-reader.yml 显式声明 contents: write 与 pull-requests: write，并开启仓库设置“允许 GitHub Actions 创建和批准 PR”，让上游发布新版本时流水线能推送更新分支并自动开 PR。

创建日期：2026-10-14 所属模块：project 状态：WIP 需求来源：Check Candle Reader Version 定时任务失败通知

1. 原始诉求

“这个项目的流水线怎么也报错了？”随后确认：“你来改。”

定时任务 Check Candle Reader Version 自 2026-10-11 起每天失败，失败当天的提交与此前成功时相同，说明原因不在代码本身。

2. 目标与边界

类型内容
目标上游 talebook/candle-reader 发布新版本时，流水线能推送 update-candle-reader-<版本> 分支并创建 PR，由仓库所有者审查后合并。
目标写权限只授予这一个 workflow，仓库默认 GITHUB_TOKEN 保持只读。
非目标不改变检查来源、版本比较、下载解压和 PR 内容；是否改为跟踪 fork 已确认维持现状，仍跟踪上游 Release。
非目标与上游脱钩的其余改动（镜像、依赖、链接等）由独立方案处理。

3. 现状、根因与证据

  • 2026-10-10 前上游没有新版本，流水线判断无需更新后直接结束，不需要任何写入，因此显示成功。
  • 2026-10-11 起上游最新 Release 为 v26.10.9，流水线进入更新分支，在推送 update-candle-reader-v26.10.9 时失败：Permission to 269289854/talebook-miku.git denied to github-actions[bot]（HTTP 403）。
  • 仓库设置 default_workflow_permissions 为 read，且 can_approve_pull_request_reviews 为 false；workflow 未声明 permissions，因此只拿到只读令牌，即便能推送也无法创建 PR。

4. 方案

  • 在 workflow 顶层新增 permissions，仅包含 contents: write（推送更新分支）和 pull-requests: write（创建 PR 并添加标签）。
  • 通过 GitHub API 开启仓库设置 can_approve_pull_request_reviews，同时保持 default_workflow_permissions: read 不变；该设置已在本方案实施时完成。
  • 新增 tests/test_candle_reader_workflow.py ，固定权限范围与 PR 步骤使用的令牌，防止回退为只读或被扩大。

5. 影响范围、风险与回滚

  • 影响范围仅限 update-candle-reader.yml 与一项仓库 Actions 设置；其他 workflow 仍使用只读默认令牌。
  • 由 GITHUB_TOKEN 创建的 PR 不会触发其他 workflow，合并前需要人工查看改动。
  • 回滚：删除 workflow 中的 permissions 块，并在仓库设置中关闭“允许 GitHub Actions 创建和批准 PR”。
