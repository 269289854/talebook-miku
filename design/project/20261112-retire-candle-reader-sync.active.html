停用上游阅读器同步

停止从 talebook/candle-reader 自动下载更新，保留项目当前维护的阅读器资源。

创建日期：2026-11-12 模块：project ACTIVE · 已验证 来源：用户每日失败邮件排查与后续停用要求

原始诉求

用户收到 Check Candle Reader Version 每日失败邮件，明确要求“不再同步上游阅读器，改完代码你自己发布 GitHub”。本次交付为代码提交与 GitHub 发布，不创建产品版本或 Release。

2026-11-12 的运行 43158141449 在推送更新分支时收到 403。仓库默认令牌只读，任务每天把 v1.1.0 与上游 v26.10.9 比较并重复尝试更新。

目标与边界

  • 停用 GitHub 当前工作流，立即停止后续定时触发。
  • 从代码中删除上游同步工作流的 schedule、repository_dispatch 和 workflow_dispatch 全部入口。
  • 保留 app/public/static/candle-reader、candle-reader-version.txt 及 creader.html，当前在线阅读继续使用已打包资源。
  • 其他 CI、构建、仓库默认权限、未合并的上游脱钩工作不在本次修改范围内。

方案与决策核对

决策选择与依据
停用范围完整删除同步任务。用户已明确不再同步，保留手动或外部事件入口会留下自动引入上游代码的路径。
现有阅读器保留所有运行文件及版本记录，停止更新与删除阅读功能分别处理。
即时生效先将 GitHub 工作流标记为 disabled_manually；再发布删除工作流的代码。
回归防护遍历真实工作流，拒绝已退役的同步 job、dispatch 事件及上游下载来源。
本地 act本次完整删除目标 workflow，删除后没有可运行的目标 job，不能执行已删除路径。使用回归测试与 GitHub 工作流状态、默认分支文件状态验证退役；不把静态检查描述为真实 job 执行。

相关修改只涉及工程配置，无界面影响。阅读器脚本、模板和产品交互均保留，因此不需要界面截图或 interface-review。

影响、风险与回滚

未来阅读器升级由本项目人工维护，不再自动下载上游发行包或创建更新 PR。其他任务仍会按各自配置运行并发送通知。

旧的权限修复 PR #2 与本次停用方向冲突，不应合并。回滚需要显式恢复已删除工作流并重新启用；只恢复文件或只启用历史记录不足以恢复完整同步。
